# Spec: Gameplay — Phase 10 Signature System (Jungle Drum Festival: Sequencing)

## Status
Draft

## Type
New Feature

## Goal
Establish the Jungle Drum Festival (Sequencing) signature system for Phase 10 (Levels 4501–5000), coordinating discrete move-based rhythmic gating, chromatic sequence pattern recognition, ordinal parade departures, and group-echo sequence duplication.

## Current State
Design documented in `phases/phase_10/03_SIGNATURE_SYSTEM_AND_MECHANICS_PHASE_10.md`, `phases/phase_10/01_PHASE_10_SCOPE_AND_RULES.md`, and `SCALING_TO_10000_LEVELS.md` §6, not yet implemented.
- Previous phases controlled flow via static locks, rotations, organic vine sprawl, or topological split/merge pads.
- Phase 10 introduces temporal ordering and chromatic sequencing where the valid resolution sequence is constrained by move modulo rhythms and FIFO departure patterns.

## Proposed Change
Implement the core sequencing architecture in `packages/puzzle_core/lib/src/systems/phase_10/`:

### 1. Jungle Drum Festival Core Mechanics
The signature system enforces strict temporal and permutation ordering without using real-time wall clocks (respecting Shared Core Standard §16):
1. **Move Modulo Rhythm Engine:**
   - Fixtures such as Drum Gates transition states solely upon player tap inputs:
     $$\text{Gate State} = \text{Pattern}[\text{TotalMovesTaken} \pmod {\text{PatternLength}}]$$
   - Turn-based cadence guarantees full player reflection without physical dexterity demands.
2. **Exit History Buffer:**
   - An in-memory FIFO ledger tracks snake departure events:
     ```dart
     class SnakeExitRecord {
       final int snakeId;
       final SnakeColor color;
       final int exitOrderIndex;
       final int moveNumber;
     }
     ```
   - Pattern matchers evaluate the trailing window $[E_{n-k+1}, \dots, E_n]$ against active gate schemas.
3. **Dual Group Echo Replication:**
   - Group A (Master) departures are recorded into a sequence vector.
   - Group B (Echo) locks require the player to evacuate Group B snakes in the exact identical chromatic order generated by Group A.

---

### 2. Engine Tick Integration (§16.17)
Every move executes the following discrete pipeline:
```
Step 1: Player Tap Input -> Active Snake Selection
Step 2: Turn Counter Increments (TotalMovesTaken += 1)
Step 3: Update M451 Rhythm Gates -> GateState = Pattern[TotalMovesTaken % Length]
Step 4: Path Clearance Evaluation (Evaluate M451 GateState, M453 Order Badges)
Step 5: Movement Execution -> Snake Exits Board:
        - Append Snake Record to ExitHistoryBuffer
        - Evaluate M452 Totem Locks (last k exits == target pattern)
        - If Group A member -> Append to GroupA_ExitOrder
        - If Group B member -> Verify against GroupA_ExitOrder[B_index]
Step 6: Gate State Resolution (Retract Totem Locks, advance Parade indices)
Step 7: Board Settled -> Ready for Next Turn.
```

---

### 3. Interaction Matrix with Earlier Systems
- **M401/M402 (Split & Merge):** If a snake splits, child snakes inherit the parent's base color for Totem matching, but possess distinct unique IDs in the Exit History Buffer.
- **M351 (Wild Vines):** Spreading vines tick every $N$ moves concurrently with drum rhythm phase shifts.
- **M301 (Perimeter Hedges):** Rotating sub-grids can reorient exit lanes toward or away from Parade Gates.
- **M251 (Portals):** Teleportation preserved; portal transit does not count as a board exit event.

---

### 4. Zero Damage & Soft-Lock Invariants
- **Harmless Bonk:** Attempting to pass an M451 Rhythm Gate on a CLOSED turn, or attempting to evacuate an out-of-order snake via an M453 Parade Gate, triggers a harmless bump animation with 0 hearts lost.
- **Move Waste Mitigation:** Players can cycle drum gate states by moving unblocked peripheral snakes without exhausting required sequence candidates.

## Risks and Open Questions
- **Echo Sequence Ambiguity:** If Group A contains multiple snakes of the same color (e.g., Red 1, Red 2), does Group B match strictly on color or on underlying snake metadata? *Resolution:* Matches strictly on `SnakeColor` to maintain transparent player feedback.
